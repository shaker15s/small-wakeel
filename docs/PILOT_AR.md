# التشغيل التجريبي (البايوت / Pilot) وبوابات الإطلاق — وكيل (PR-015 / الخطة §13 + §25)

## المبدأ الحاكم
**لا إطلاق تلقائي لمجرد اكتمال الخطة.** القرار قرار مُوثَّق (موافقة إصدار من المالك)
مرفوع على أدلة دائمة على SHA محدد — والنظام كله مبني ليَقول «غير مسجل» و«not_connected»
بصوت عالٍ بدل أن يملأ الفراغ بأرقام أو ادعاءات.

## ماذا يقيس «سجل المنفعة» (قبل/بعد)
`GET /api/pilot?businessId=&days=` يجمع — **قياسًا من السجلات الملحقة فقط**:

| الرقم | المصدر (قياس نظام) | ملاحظة الصراحة |
|---|---|---|
| جولات مكتملة + p50/p95 مدة الجولة | `AgentEvent`: `turn.started` ↔ `turn.ended` بنفس `traceId` | الجولة «started» بلا «ended» لا تُحسب — لا وقت مُختلَق |
| أدوات منفذة (بعدد كل أداة) | `tool.executed` | — |
| رفضات / أعطال أدوات / أخطاء مزود | `tool.refused` / `tool.failed` / `provider.error` | — |
| تصحيحات | `correction` | — |
| توضيحات (أسئلة المتابعة) | `PendingRequest` بحالاتها (awaiting/resolved/cancelled) | — |
| معاملات + **SUCCEEDED بلا اعتماد بشري** | `Operation` مقابل `AuditEvent operation.approved` لكل ref | **>0 = حاجز إطلاق** — التقرير يكشفها ولا يخفيها |
| مهام عالقة | `ScheduledTask` بحالات pending/retry_wait/failed | — |
| فلات الموديل الاحتياطي | `UsageEvent.fallback` | — |
| **تكلفة التشغيل بالمال** | — | **`null` + «غير مسجل»**: السجلات تحسب توكنز لا مالًا؛ بلا سعر مثبت لا رقم |
| **الخط الأساس (قبل)** | `POST /api/pilot/baseline` — قياس **المالك** (مصدره `owner_reported`) | المجهول يبقى `null` («غير مسجل») — لا 0-كـ-مجهول |

القاعدة الذهبية: **قبل = قياس المالك، بعد = قياس النظام — ولا يُحسب النظام «وفراً»
ذاتيًا**؛ مقارنة الطرفين للمالك، والتقرير يعرض المصدرين منفصلين.

## خطة التشغيل التجريبي (خطوة بخطوة)
1. **مجموعة صغيرة من منشآت حقيقية** بموافقة صريحة؛ بيانات محدودة أو مستوردة بعناية
   (`/api/items/reconcile` — dry-run → اعتماد → read-back؛ لا bulk import صامت).
2. **كل قطاع من العشرة حاضر في validation**؛ قطاع لم تجتز بوابته «لا يُعلن مدعومًا
   تجاريًا» ولا يُستبدل فشله بادعاء عام (اختبار: `tests/unit/sector-contracts.test.ts`).
3. **اتفاق على سير عمل واحد لكل نشاط** يُقاس قبل/بعد: المالك يسجل خط أساسه
   (`POST /api/pilot/baseline` — اسم النشاط، كم مرة، كم دقيقة بالطريقة القديمة، أخطاء).
4. **كل معاملة مالية خلف اعتماد المالك افتراضيًا** — المسودة لا تغيّر السجل الرسمي.
   الكاشير والاستقبال لا يعتمدون مطلقًا؛ تفويض المشرف للعمليات R1/R2 فقط يتطلب
   `WAKIL_ALLOW_DELEGATED_APPROVALS=1`، وR3 يظل للمالك. الصوت/القراءة/الاقتراح لا ينفذ مالًا أبدًا
   (مُختبر: `succeededWithoutApproval` في تقرير البايوت يجب أن يبقى 0).
5. **مراجعة يومية** من التقرير نفسه: التوضيحات (`clarifications.awaiting`)، الإلغاءات،
   أخطاء فهم الأسماء/الوحدات (تصحيحات + رفضات)، الموديل الاحتياطي (`fallbacks`)،
   المهام العالقة (`stuckTasks`)، الأخطاء (`toolFailures`, `providerErrors`)،
   والتكلفة (توكنز مقاسة؛ مال «غير مسجل» حتى يثبت سعر).
6. **لا يُستدل على الاستعداد للدفع من الإعجاب** — اختبار عرض سعر حقيقي/قرار دفع واضح
   مقابل قيمة مثبتة (معايير GO التجارية §25).
7. **إيقاف فوري** لأي تكامل/Plugin عند خطأ مال أو عزل أو اتصال غير متوقع
   (`/api/plugins` — تعطيل فوري + سجل؛ «kill switch» جزء من عقد الـ plugin).
8. **مقابلات خروج قصيرة**: آخر مرة استخدم فيها المالك الملخص/متابعة الدَّين لاتخاذ قرار،
   وما الذي عاد يفعله بالطريقة القديمة.

## بوابة GO للإطلاق العام (§13) — تُقيَّم آليًا على SHA محدد
`npm run pilot:gate -- --report pilot-gate.json`
(= `node scripts/pilot-gate.mjs --report pilot-gate.json`)

البوابة **تنفذ** الأدلة لا تدّعيها: تتشغيل بطاريات اختبارات القطاعات والمال والموصِّلات
فعليًا، تستهلك تقرير `model:acceptance` (يجب أن يكون `liveAcceptance:true` — جولة mock
تُثبت عقد الـ adapter فقط وتُختم `liveAcceptance:false`)، وتفحص وجود وثائق
الخصوصية/الشروط/التدقيق المستقل/السعة.

| # | العنصر | الأدلة المطلوبة |
|---|---|---|
| 1 | P0–P8 مغلقة بأدلة دائمة | وثائق الـ verification الملتزمة على الـ SHA |
| 2 | القطاعات العشرة اجتازت قبولها | تشغيل `sector-contracts` الآن |
| 3 | `model:acceptance` + Live من بيئة حقيقية | تقرير `liveAcceptance:true` (لا mock) |
| 4 | اعتماد بشري لكل مالي + crash/replay/concurrency/reversal | تشغيل 8 ملفات اختبارات المالية الآن |
| 5 | Companion/موصِّلات على المستويات المجتازة فقط | تشغيل بطارية companion/reconciliation/plugin + `not_connected` للمتبقي |
| 6 | CI مستضاف + artifacts على SHA + درills نسخ/تدوير | `.github/workflows` فعلي + تشغيلات مرئية على الـ SHA |
| 7 | تدقيق أمني مستقل + خصوصية/شروط/تشغيل/مراقبة | الوثائق + أثر تدقيق ملتزم |
| 8 | تكلفة وحدة + سعة + حدود استخدام + rollback + خطة حوادث | بيانات أسعار + قياس سعة + الوثائق |

**النتيجة**: `NO-GO` (الافتراضي) أو `GO_CANDIDATE` — ولا يوجد `GO` من سكريبت.
`GO_CANDIDATE` تعني: كل الأدلة متوفرة على هذا الـ SHA، والخطوة الأخيرة موافقة إصدار
موثقة من المالك مرفقة بالتقرير. اليوم (بيئة تطوير بـ mock) النتيجة الصادقة **NO-GO**
والنواقص مسمّاة واحدًا واحدًا في التقرير — هذه النواقص هي قائمة العمل الباقية.

## الحالة الآن — بلا ادعاء
- قياس المنفعة في البايوت: **implemented + مُختبَر** على السجلات (قياس حقيقي من ledgers).
- القبول الصوتي/الموديلي الحي، CI المستضاف، التدقيق المستقل، سياسة الخصوصية/الشروط،
  قياس السعة: **غير منفَّذة** — تظهر `not_met` في البوابة ولا تُخفى.
- الإطلاق العام: **NO-GO** حتى تُغلق كل البوابات الثماني بأدلة دائمة على SHA محدد.

## التشغيل (tuning)
- `POST /api/pilot/baseline` — حقول: `workflow` (إلزامي) + `tasksCount`/`minutes`/`errors`
  (أرقام ≥ 0 أو `null` للمجهول) + `note`.
- `GET /api/pilot?businessId=&days=` — نافذة حتى 365 يومًا.
- `npm run pilot:gate` — لا تحتاج متغيرات؛ إذا وُجدت `WAKIL_ACCEPTANCE_*` تختبر البوابة
  المزود الحي وإلا تُختم البيئة mock.
